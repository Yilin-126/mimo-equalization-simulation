# C/Python均衡算法数值一致性验证报告

## 1. 验证目的

本次验证用于检查C语言实现的ZF和MMSE均衡算法是否与已冻结的Python参考结果保持数值一致。

采用先固定Python测试向量、再验证C语言输出的方式，避免为了使测试通过而修改参考数据。

## 2. 测试环境与文件

开发环境：

- Windows
- Python 3.11
- GCC 16.2.0（MSYS2 UCRT64）
- NumPy complex128
- C double complex

主要文件：

- `c_src/equalizer.c`：C语言均衡算法实现
- `c_src/equalizer.h`：接口声明
- `tests/fixtures/equalizer_reference.json`：冻结Python参考数据
- `scripts/check_c_equalizer.py`：数值一致性验证脚本
- `scripts/benchmark_c_python.py`：耗时对比脚本

## 3. 验证方法

测试数据覆盖以下四类信道：

1. 1×1正常信道
2. 1×1弱信道
3. 2×2正常信道
4. 2×2近奇异信道

每种信道分别设置0 dB和20 dB两种SNR条件。

共生成8组测试场景，每组分别比较ZF和MMSE结果，因此总计16项数值比较。

输入数据包括：

- 复数信道矩阵H
- 接收信号向量y
- 噪声方差
- Python预期输出

复数采用 `[real, imag]` 格式存储，矩阵按行优先顺序传递。

## 4. 误差评价指标

采用最大绝对复数误差：

`E_max = max(|x_C - x_Python|)`

验收阈值为：

`E_max <= 1e-8`

每项比较独立判断是否通过。

## 5. 固定参考向量验证结果

| 测试项目 | 结果 |
|---|---|
| 测试场景 | 8组 |
| 比较算法 | ZF、MMSE |
| 数值比较 | 16项 |
| 通过数量 | 16项 |
| 最大绝对误差 | 1.379e-10 |
| 验收阈值 | 1e-8 |
| 总体结果 | 通过 |

最大误差出现在2×2近奇异信道、0 dB条件下的ZF均衡测试。

所有测试项均满足预设阈值。

这说明当前C实现与冻结Python参考值在所测试输入条件下具有良好的数值一致性。

## 6. 不同规模耗时测试

在完成固定参考向量验证后，进一步比较当前Python函数与C/ctypes调用路径的运行时间。

测试覆盖：

- 天线配置：1×1、2×2
- 独立均衡向量数量：64、256、1200
- 算法：ZF、MMSE

合计12组测试。

每组输入保持一致，经过预热后重复计时5次，使用耗时中位数作为结果。

加速比定义：

`Speedup = T_Python / T_C_ctypes`

### 6.1 实测性能

| 配置 | K | ZF加速比 | MMSE加速比 |
|---|---:|---:|---:|
| 1×1 | 64 | 6.68× | 3.27× |
| 1×1 | 256 | 7.19× | 2.95× |
| 1×1 | 1200 | 7.04× | 3.06× |
| 2×2 | 64 | 8.38× | 3.57× |
| 2×2 | 256 | 8.47× | 3.46× |
| 2×2 | 1200 | 8.42× | 3.33× |

12组耗时测试均通过对应的数值一致性检查。

本轮基准测试的最大绝对误差约为 `4.58e-15`。

### 6.2 性能分析

测试表明，在当前执行路径和测试环境下：

- ZF算法的C/ctypes调用路径比Python逐向量实现快约6.68–8.47倍。
- MMSE算法快约2.95–3.57倍。
- 各组测试保持相同的信道矩阵与接收数据。

需要注意，这一结果包含ctypes接口调用、数组转换及输出分配开销，不代表纯C计算核的独立耗时。

Python版本使用NumPy线性代数函数，C版本使用针对小规模矩阵的求解方法，因此本结果反映的是当前实现路径的性能差异，而不是编程语言本身的普遍性能差异。

## 7. 局限性

1. C版本目前只支持1×1与2×2方阵信道。
2. 冻结参考数据仅覆盖选定的正常、弱及近奇异信道。
3. 耗时测试未单独测量纯C计算核执行时间。
4. 尚未测试更大天线阵列及批量C接口。
5. 不同运行环境、编译选项及CPU负载可能影响实际耗时。

## 9. 结论

当前C语言ZF/MMSE均衡模块完成了固定Python参考向量验证，16项数值比较全部通过，最大绝对误差满足1e-8的要求。

在当前1×1、2×2及三种独立均衡向量数量条件下，C/ctypes执行路径表现出一定的耗时优势。

后续仍需补充纯C计算核计时和更广泛的异常输入测试，进一步明确模块的计算性能与适用边界。


## 10. 补充：原生C计算核性能验证

在完成C/ctypes接口级性能测试后，进一步使用独立C语言程序测量原生均衡函数的执行时间。

测试覆盖1×1、2×2天线配置，以及64、256、1200个独立均衡向量，共12组配置。

实测单次调用耗时范围：

- 1×1 ZF：16.115–16.313 ns
- 1×1 MMSE：26.376–27.834 ns
- 2×2 ZF：51.948–52.922 ns
- 2×2 MMSE：85.808–87.397 ns

原生C测试不经过Python/ctypes接口，但仍包含C函数调用与循环开销。

该结果与前面的C/ctypes基准测试分别反映两种执行路径，尚不能精确量化ctypes接口本身的时间开销。

对应测试源文件：
